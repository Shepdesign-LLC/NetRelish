# P1 — The Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Supabase backend where a signed-in client can create a jar, add an item, find it by full-text search — and a second account provably cannot see any of it.

**Architecture:** Migrations are files in `supabase/migrations/` AND applied via the Supabase MCP `apply_migration`, so version control and applied state agree. The merge rule lives in one `plpgsql` function because there are three clients and three implementations would drift. Tests are SQL, run through `execute_sql`, asserting with `RAISE EXCEPTION` so a failure is loud.

**Tech Stack:** Supabase (project `qiyqlbaggqthcuxslwyk`, region us-east-1, Postgres 17.6), pgvector 0.8.2, TypeScript for the generated client.

**Spec:** `docs/superpowers/specs/2026-08-19-p1-core-design.md`

---

## Verified before planning

These were probed against the live project, not assumed:

- `vector` 0.8.2 is available (not yet installed). `pgcrypto` and `uuid-ossp` are installed, so `gen_random_uuid()` works.
- **RLS is testable without real signups.** Inside a transaction,
  `set_config('role','authenticated',true)` plus
  `set_config('request.jwt.claims', '{"sub":"<uuid>","role":"authenticated"}', true)`
  makes `auth.uid()` return that uuid and policies apply. Proven: acting as A,
  a 2-row table returned 1 row; A deleting B's row affected 0 rows; A
  reassigning its own row to C was **BLOCKED** by `with check`.
- **Gotcha the tests must handle:** while the role is `authenticated`, you
  cannot write to a temp results table. Capture outcomes into plpgsql
  variables, `set_config('role','postgres',true)`, *then* record them.

### Task 3: Row-level security

**Files:** Create `supabase/migrations/0003_rls.sql`

- [ ] **Step 1: Write the migration**

Both `using` and `with check` are required. `using` alone lets a user reassign a row to someone else's `user_id` — proven blocked only by `with check`.

```sql
do $$
declare t text;
begin
  foreach t in array array['jars','items','tabs','labels','item_labels',
                           'recipes','suggestion_feedback','embeddings']
  loop
    execute format('alter table %I enable row level security', t);
    execute format('drop policy if exists owner_all on %I', t);
    execute format(
      'create policy owner_all on %I for all using (user_id = auth.uid()) with check (user_id = auth.uid())', t);
  end loop;
end $$;
```

- [ ] **Step 2: Apply** via `apply_migration`, name `rls`.

- [ ] **Step 3: Verify every table has RLS on and exactly one policy**

```sql
select c.relname, c.relrowsecurity, count(p.polname) as policies
from pg_class c
left join pg_policy p on p.polrelid = c.oid
where c.relnamespace = 'public'::regnamespace and c.relkind='r'
group by c.relname, c.relrowsecurity order by c.relname;
```

Expected: 8 rows, every `relrowsecurity` = `true`, every `policies` = 1.

- [ ] **Step 4: Check Supabase's own advisor agrees**

Call the MCP `get_advisors` with `type: security`. Expected: no findings of type "RLS disabled". Report anything else it says rather than silently ignoring it.

### Task 5: The merge function

**Files:** Create `supabase/migrations/0004_sync_push.sql`

- [ ] **Step 1: Write the function**

`client_synced_at` is load-bearing: without it the function cannot tell a real prose conflict from a client that simply has not pulled yet, and every stale laptop would spawn conflict copies.

```sql
create or replace function sync_push(payload jsonb, client_synced_at timestamptz)
returns jsonb
language plpgsql
security invoker
as $$
declare
  row_in      jsonb;
  existing    items%rowtype;
  merged      items%rowtype;
  new_ts      jsonb;
  fld         text;
  incoming_ts timestamptz;
  stored_ts   timestamptz;
  results     jsonb := '[]'::jsonb;
  conflict_id uuid;
begin
  for row_in in select * from jsonb_array_elements(payload)
  loop
    select * into existing from items where id = (row_in->>'id')::uuid;

    if not found then
      insert into items (id, user_id, jar_id, kind, url, title, body, meta,
                         created_at, touched_at, field_ts, updated_at)
      values ((row_in->>'id')::uuid, auth.uid(),
              nullif(row_in->>'jar_id','')::uuid, row_in->>'kind',
              row_in->>'url', row_in->>'title', row_in->>'body',
              coalesce(row_in->'meta','{}'::jsonb),
              coalesce((row_in->>'created_at')::timestamptz, now()),
              coalesce((row_in->>'touched_at')::timestamptz, now()),
              coalesce(row_in->'field_ts','{}'::jsonb), now())
      returning * into merged;
      results := results || to_jsonb(merged);
      continue;
    end if;

    -- conflict copy: both sides edited prose since they last agreed
    incoming_ts := (row_in->'field_ts'->>'body')::timestamptz;
    stored_ts   := (existing.field_ts->>'body')::timestamptz;

    if incoming_ts is not null
       and row_in->>'body' is distinct from existing.body
       and stored_ts is not null
       and stored_ts > client_synced_at then
      conflict_id := gen_random_uuid();
      insert into items (id, user_id, jar_id, kind, url, title, body, meta,
                         created_at, touched_at, field_ts, updated_at)
      values (conflict_id, auth.uid(), existing.jar_id, existing.kind,
              existing.url, existing.title, row_in->>'body',
              coalesce(row_in->'meta','{}'::jsonb)
                || jsonb_build_object('conflict_of', existing.id,
                                      'conflict_at', now()),
              existing.created_at, now(),
              coalesce(row_in->'field_ts','{}'::jsonb), now());
      results := results || jsonb_build_object('conflict_copy', conflict_id,
                                               'of', existing.id);
      continue;
    end if;

    -- field-level LWW; ties keep stored
    merged := existing;
    new_ts := existing.field_ts;
    for fld in select jsonb_object_keys(coalesce(row_in->'field_ts','{}'::jsonb))
    loop
      incoming_ts := (row_in->'field_ts'->>fld)::timestamptz;
      stored_ts   := (existing.field_ts->>fld)::timestamptz;
      if stored_ts is null or incoming_ts > stored_ts then
        new_ts := new_ts || jsonb_build_object(fld, incoming_ts);
        case fld
          when 'title'  then merged.title  := row_in->>'title';
          when 'body'   then merged.body   := row_in->>'body';
          when 'url'    then merged.url    := row_in->>'url';
          when 'jar_id' then merged.jar_id := nullif(row_in->>'jar_id','')::uuid;
          when 'meta'   then merged.meta   := row_in->'meta';
          when 'deleted_at' then merged.deleted_at := (row_in->>'deleted_at')::timestamptz;
          else null;
        end case;
      end if;
    end loop;

    update items set title=merged.title, body=merged.body, url=merged.url,
                     jar_id=merged.jar_id, meta=merged.meta,
                     deleted_at=merged.deleted_at,
                     field_ts=new_ts, updated_at=now()
    where id = existing.id
    returning * into merged;
    results := results || to_jsonb(merged);
  end loop;

  return results;
end $$;
```

`security invoker` is deliberate — the function runs as the caller, so RLS still applies inside it. `security definer` would bypass every policy in Task 3 and hand any signed-in user the whole database.
